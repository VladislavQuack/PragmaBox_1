# РИТМ — дашборд тренера (Telegram Mini App)

Таймлайн дня, клиенты, абонементы, оплаты и напоминания для персональных тренеров.
Next.js (App Router) + PostgreSQL через Drizzle ORM.

## Два режима

- **Витринный (по умолчанию).** Технических страниц нет, в профиле — цель и цены, виджеты, демо-данные и помощь.
  Так приложение показывают потенциальным клиентам.
- **Режим владельца.** Переменная `SHOW_GUIDES=1` открывает страницы `/setup` (подключение Telegram)
  и `/deploy` (публикация на Vercel) и ссылки на них в настройках.

Переменная читается на сервере при каждом запросе, так что переключение не требует пересборки —
достаточно перезапустить приложение.

## Переменные окружения

| Переменная | Обязательна | Зачем |
| --- | --- | --- |
| `DATABASE_URL` | да | Строка подключения к PostgreSQL. У облачных баз нужен `?sslmode=require` |
| `TELEGRAM_BOT_TOKEN` | на проде да | Токен бота из [@BotFather](https://t.me/BotFather). Пока пуст — приложение работает в демо-режиме |
| `ALLOW_BROWSER_DEMO` | нет | `1`, чтобы открывать приложение в браузере даже при заданном токене (для отладки) |
| `SHOW_GUIDES` | нет | `1` — показать технические инструкции `/setup` и `/deploy`. Пусто — витринный режим для показа клиентам |
| `BOT_ADMIN_IDS` | нет | Telegram ID владельца (можно несколько через запятую). Бот присылает сюда отзывы, ответы «сколько готов платить», новых тренеров, оплаты и обращения по оплате. Владельцу же доступны `/stats`, `/refund`, `/sync`, `/reply` и проверка оплаты в бете. Свой ID покажет команда `/id` в боте |
| `APP_URL` | нет | Постоянный адрес приложения, например `https://pragmabox.ru`. На Vercel определяется сам — задавай, только если хостинг другой |

Пример — в файле `.env.example`.

## Локальный запуск

```bash
npm install
npx drizzle-kit push   # создаёт таблицы в локальной базе
npm run dev
```

## Публикация на Vercel

### 1. База данных

Создай проект на [neon.tech](https://neon.tech) (бесплатный тариф) и скопируй
**Pooled connection string** — она рассчитана на serverless.

### 2. Код на GitHub

Создай на GitHub **пустой** приватный репозиторий (без README и .gitignore),
затем из папки проекта:

```bash
git init
git add .
git commit -m "РИТМ: первая версия"
git branch -M main
git remote add origin https://github.com/ЛОГИН/ritm-trainer.git
git push -u origin main
```

Вместо пароля GitHub требует Personal Access Token:
`Settings` → `Developer settings` → `Personal access tokens` → `Tokens (classic)`,
права `repo`.

Папки `node_modules`, `.next` и файл `.env` с паролями исключены через `.gitignore`.
Проверить перед отправкой: `git ls-files | grep env` — в выводе должен быть только `.env.example`.

Последующие обновления:

```bash
git add .
git commit -m "что изменил"
git push
```

### 3. Проект на Vercel

На [vercel.com](https://vercel.com): `Add New…` → `Project` → выбрать репозиторий.
Next.js определяется автоматически, настройки сборки менять не нужно.

В разделе `Environment Variables` добавь `DATABASE_URL` и `TELEGRAM_BOT_TOKEN`,
затем нажми `Deploy`.

Если переменные добавлены после первой сборки, запусти пересборку:
`Deployments` → `Redeploy`.

### 4. Таблицы в боевой базе

Один раз локально. Файл `.env` содержит секреты и не хранится в GitHub — поэтому в скачанном проекте будет только `.env.example`. В Windows PowerShell из корня проекта создай локальную копию:

```powershell
Copy-Item .env.example .env
notepad .env
```

В `.env` замени значение `DATABASE_URL` на строку подключения Neon, сохрани файл, затем выполни:

```powershell
npm install
npx drizzle-kit push --config=drizzle.config.prod.ts
```

Конфиг сам прочитает `DATABASE_URL` из `.env`. Не загружай `.env` в GitHub. Локальный `drizzle.config.json` используется только песочницей.

Ту же команду запускай после обновлений, которые меняют схему базы: она добавит новые таблицы и не трогает данные.
Если `drizzle-kit` вдруг спросит, очистить ли таблицу (`truncate`), всегда выбирай **No** — это просто Enter.

Без терминала: для каждого такого обновления в папке `sql/` лежит готовый скрипт. Открой Neon → **SQL Editor**,
вставь файл целиком и нажми **Run** — результат тот же, что у `drizzle-kit push`, а повторный запуск ничего не сломает.
Например, таблицы беты — `sql/2026-10-beta.sql`, таблицы Premium — `sql/2026-11-premium.sql`.

### 5. Адрес в BotFather

`/mybots` → бот → `Bot Settings` → `Menu Button` → `Edit menu button URL` → адрес с Vercel.
Если мини-апп создавался через `/newapp`, поправь URL и там (`/myapps`).

Ещё включи главное мини-приложение: `/mybots` → бот → `Bot Settings` → `Configure Mini App` →
`Enable Mini App` → тот же адрес. Иконка на главном экране телефона открывает именно его — без этого
она не запустит приложение. Включено ли — видно на `/api/telegram/setup` (поле `mainMiniApp`).

## Бот

Бот — не просто кнопка запуска: он рассказывает о приложении, принимает отзывы, продаёт Premium за звёзды,
выдаёт ссылку-приглашение и кнопку «Установить на телефон» (иконка мини-аппа на главном экране, Bot API 8.0+).

Команды в бете: `/start`, `/app`, `/install`, `/review`, `/invite`, `/bonus`, `/help`.
После беты в меню вместо `/bonus` появляются `/premium`, `/terms` (условия) и `/paysupport` (помощь с оплатой) —
их Telegram требует от ботов, которые принимают оплату. `/id` показывает твой Telegram ID.
Любое обычное сообщение боту считается отзывом, а ответ на сообщение `/paysupport` — обращением по оплате.

Команды владельца (`BOT_ADMIN_IDS`), в меню их нет:

- `/stats` — тренеры, пробный период, сколько человек открывали оплату и сколько оплатили;
- `/refund` — последние оплаты, кнопка возвращает звёзды (бот переспросит) и сокращает Premium;
- `/sync` — сверить неоплаченные счета за неделю с Telegram, если сообщение об оплате не дошло;
- `/reply ID текст` — ответить пользователю от имени бота (ID есть в обращении).

Подключается сам: при первом открытии приложения на проде сервер регистрирует вебхук
`/api/telegram/webhook`, меню команд и описание бота (описание — только если в BotFather оно пустое).
Проверить вручную — открыть в браузере `https://<адрес-приложения>/api/telegram/setup`: там видно адрес вебхука и последнюю ошибку Telegram.

Запросы от Telegram подписаны секретом, который выводится из токена бота, — чужой сервер подделать их не сможет.

### Иконка на главном экране

Кнопка «Установить на телефон» в боте и карточка в профиле открывают окно установки (`InstallSheet`).
Как это работает в Telegram:

- **Android** — Telegram просит систему закрепить ярлык. Ответ приходит, только если иконка появилась.
  На Xiaomi, Redmi, POCO, Huawei, Honor и некоторых других у Telegram по умолчанию выключено разрешение
  «Ярлыки на рабочем столе» — система отказывает молча. Поэтому, если ответа нет 3 секунды, окно показывает,
  что включить, с путём для марки телефона (её Telegram передаёт в User-Agent).
- **iPhone** — Telegram открывает Safari, дальше «Поделиться» → «На экран „Домой“». Окно подсказывает это заранее.
- **Компьютер и веб-версии** — не умеют: окно предлагает открыть бота на телефоне.

Иконка называется как бот и с его аватаркой — их меняют в BotFather (`/mybots` → бот → `Edit Bot`).

## Бета-тест

Бета закончилась: в `src/lib/beta.ts` стоит `BETA = false`, работает платная версия (см. «Premium и оплата звёздами» ниже).

Пока шла бета, лимита клиентов не было, а за помощь проекту тренер получал Premium после запуска платной версии:
за отзыв — 6 месяцев, за друга, который прошёл первую настройку, — 12 месяцев (бонусы складываются).
Заработанные месяцы прибавляются к сроку Premium при первом входе после запуска, новые бонусы не начисляются.

Если после запуска что-то пойдёт не так, можно временно вернуть `BETA = true`: лимит выключится, оплата закроется,
снова начнут начисляться бонусы беты, а уже купленный Premium сохранится.

Данные беты лежат в отдельных таблицах: `feedback` (отзывы и ответы о цене), `rewards` (бонусы), `referrals` (приглашения).
Если код выехал раньше, чем таблицы созданы, приложение работает, а бонусы просто ждут `drizzle-kit push`
(или скрипт `sql/2026-10-beta.sql` в SQL Editor Neon).

## Premium и оплата звёздами

Без Premium можно вести до 3 клиентов, остальное бесплатно. Premium снимает лимит.
Новым тренерам — 14 дней Premium бесплатно после первой настройки. Цены и сроки — в `src/lib/subscription.ts`
(сейчас месяц — 200 ⭐, год — 2000 ⭐), там же текст условий для `/terms`.

Оплата — звёздами Telegram (валюта `XTR`): цифровые товары в мини-аппах Telegram разрешает продавать только за них.
Договор, карта и настройки в BotFather не нужны. Покупки разовые, без автосписаний: срок прибавляется к текущему.
Платить можно в приложении (Профиль → карточка Premium, баннер лимита на «Клиентах») и прямо в боте (`/premium`).

Как это устроено (`src/lib/server/premium.ts`):

- приложение просит счёт (`POST /api/premium`), сервер создаёт строку в `payments` и ссылку `createInvoiceLink`,
  приложение открывает её через `Telegram.WebApp.openInvoice`;
- перед списанием Telegram спрашивает бота (`pre_checkout_query`), бот проверяет счёт и отвечает за 10 секунд;
- после списания бот получает `successful_payment`, отмечает оплату и продлевает срок в таблице `premium`.
  Повторная доставка того же платежа ничего не начислит второй раз. Если сообщение задержалось, приложение
  само находит платёж через `getStarTransactions` (`/api/premium/check`), а владелец может запустить `/sync`;
- возврат — `/refund` в боте (метод `refundStarPayment`).

Звёзды копятся на балансе бота (виден с аккаунта владельца). Вывести можно через Fragment, не раньше чем через
21 день после оплаты, от 1000 ⭐. Для вывода нужен облачный пароль в Telegram.

### Запуск после беты

1. Выполни `sql/2026-11-premium.sql` в Neon → SQL Editor. Проверить — `/api/health`, поле `premiumTables: true`.
2. Пока `BETA = true`, карточку «Premium — проверка оплаты» в профиле и `/premium` в боте видит только владелец
   (`BOT_ADMIN_IDS`). Купи «Проверку оплаты» за 1 ⭐ и верни звезду через `/refund`.
3. Поставь `BETA = false` в `src/lib/beta.ts`. Включатся лимит Free, пробный период и оплата для всех. Тем, кто уже
   пользуется, 14 дней Premium выдаются с первого входа после запуска, а бонусы беты сами прибавляются к сроку
   (бот напишет об этом). Новые бонусы за отзывы и друзей после беты не начисляются. Меню команд и описание бота
   обновятся сами (своё описание из BotFather бот не трогает).

Если таблиц Premium нет, приложение работает как в бете: лимит не включается, а оплата показывает «вот-вот заработает».

Вручную (Neon → SQL Editor), если нужно помочь тренеру:

```sql
-- Premium на 30 дней тренеру с Telegram ID 123456789 (срок прибавится к текущему)
INSERT INTO premium (trainer_id, active_until)
SELECT id, now() + interval '30 days' FROM trainers WHERE tg_id = '123456789'
ON CONFLICT (trainer_id) DO UPDATE
SET active_until = greatest(coalesce(premium.active_until, now()), now()) + interval '30 days';

-- Premium навсегда
UPDATE trainers SET subscription_tier = 'premium' WHERE tg_id = '123456789';
```

## Как считаются деньги

Правила в одном месте — `src/lib/analytics.ts` (`incomeSummary`, `debtSummary`) и `src/lib/packages.ts`:

- **Заработано** — сумма проведённых тренировок за текущий месяц. Занятие по абонементу приносит долю его цены
  (цена абонемента ÷ количество занятий).
- **Получено** — часть заработанного, за которую деньги уже пришли. Занятие по абонементу оплачено,
  когда оплачен сам абонемент.
- **Долг** — проведённые разовые тренировки без оплаты плюс неоплаченные абонементы на всю сумму
  (любые, а не только последний). Занятия из абонемента отдельным долгом не считаются — иначе долг удваивался бы.
- Занятие списывается с последнего абонемента, где они ещё остались, когда тренировка отмечена проведённой.
  Разовая тренировка («Уже оплачено» / «Оплатит позже» в мастере) абонемент не трогает.
- Демо-клиенты помечены заметкой (`src/lib/demo.ts`): «Убрать демо-данные» удаляет только их.

## Как устроена авторизация

Telegram передаёт мини-аппу строку `initData`, подписанную токеном бота.
Клиент шлёт её в заголовке `X-Telegram-Init-Data`, сервер проверяет HMAC-подпись
(`src/lib/server/auth.ts`) и находит или создаёт тренера.

Все таблицы содержат `trainer_id`, и каждый запрос ограничен текущим тренером,
поэтому чужие данные недоступны.

Без `TELEGRAM_BOT_TOKEN` приложение пускает всех под общим «Демо-тренером» —
это удобно для разработки, но на проде токен обязателен.
